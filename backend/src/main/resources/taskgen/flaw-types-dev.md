What a flaw is (E3, 2026-11-26 g6): the starter code follows the AI's usual default (idiomatic Java, common sense), and that default is wrong because a business rule written only in the materials says otherwise. The rule appears as records in NOTES.md or the description (a settled past case on another input, a contract or policy excerpt quoted as a record, an operations log line), never as a rule sentence aimed at the candidate. An AI that rewrites the code idiomatically without reading the materials must still get it wrong.
Do not use generic bugs that idiomatic rewriting fixes by itself: int overflow, floating-point accumulation, month-end date arithmetic, DST day length, null or empty input, stale cache, off-by-one in loops. In g6 the solo AI fixed all of them without opening a single needed file.
